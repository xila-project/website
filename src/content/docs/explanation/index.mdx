## Follow the question you have

**How can the same Xila code run on an MCU, a native host, and in a browser?**

Read [development environments and targets](/explanation/development-environments) for the relationship between toolchains, validation targets, and platform ownership.

**How will application packages be built, published and installed?**

Read [package management architecture](/explanation/package-management) for the separation of portable Rust tooling, the static package registry and planned on-device trust/installer integration.

**How does the browser version keep a persistent disk?**

Read [browser storage](/explanation/browser-storage) for the relationship between OPFS, the in-memory disk image, autosave, and durability.

**What happens when Xila executes a WebAssembly guest?**

Read the [WASM runtime](/explanation/architecture/executables/wasm) for Wasmi integration, WASI imports, and cooperative execution.

**How do guest graphics calls cross into the host runtime?**

Read [graphics bindings](/explanation/architecture/executables/bindings) for the ownership and memory boundary between guest handles and host objects.

## When your question changes

Explanation is intentionally not a task guide or an API catalogue. When you know _why_ a part of Xila works the way it does and want to do something with it, continue with the [how-to guides](/how-to/). When you need an exact command, limit, symbol, or API contract, use the [reference section](/reference/).
