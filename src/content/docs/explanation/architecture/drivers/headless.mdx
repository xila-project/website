The Platforms `drivers_headless` crate provides screen and audio implementations for native host platforms without a display window.

## Context

A runtime can supply these implementations where Xila expects graphics or audio interfaces, without displaying a window.

## How it works

The screen character device tracks a drawing area and resolution. It validates pixel writes and accepts valid data without displaying it. The audio output reads available whole frames from the audio system into caller-provided storage.

## Design choices and trade-offs

The screen does not retain a framebuffer. Its read operation is unsupported, and it reports that it has not resized. The audio reader rejects a buffer whose size is not a whole number of frames.

## Limits

The crate is restricted to Linux, macOS, and Windows targets.
