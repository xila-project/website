The Core repository's `drivers_core` crate supplies minimal devices and optional Wi-Fi and Bluetooth mocks.

## Context

These implementations use the device interfaces shared with the virtual file system (VFS).

## How it works

The null character device returns zero bytes on reads and accepts all bytes on writes. The native and browser examples mount it at `/devices/standard_io/null`. The browser example also uses it for standard input, output, and error.

The `wifi_mock` feature exposes a deterministic Wi-Fi controller and runner. The native example can register it as `wlan0` for control-plane testing.

The `bluetooth_mock` feature exposes a deterministic in-memory Bluetooth Low Energy HCI controller with configurable peers and attribute tables, for tests of the [Bluetooth](/explanation/architecture/subsystems/bluetooth/) subsystem. It runs on logical ticks that the test advances explicitly and never opens a host Bluetooth device.

## Design choices and trade-offs

The crate is `no_std`. The mocks are feature-gated and do not operate a host radio.
