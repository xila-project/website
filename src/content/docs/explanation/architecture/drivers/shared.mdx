The Platforms `drivers_shared` crate provides devices shared by multiple runtimes.

## Context

The native and browser examples combine these devices with platform-specific implementations.

## How it works

Both examples mount random and hashing devices at `/devices/random/source` and `/devices/compute/hasher`. The native example also mounts shared HTTP and HTTPS devices at `/devices/network/http_client` and `/devices/network/https_client`. With the neural-network feature, both mount a loader at `/devices/nn/cpu`.

### Terminal input

The terminal line editor echoes accepted input. Backspace or Delete removes the last UTF-8 character. Ctrl-U erases the line. Ctrl-C discards the line, echoes `^C` and a newline, and queues an empty line. Ctrl-D reports end of input on an empty line and is ignored on a nonempty line. Tab inserts one space. Other control bytes are ignored. Escape sequences are consumed.

CR or LF commits the line with a newline and echoes CRLF. An LF immediately following CR is consumed. If the completed queue lacks room for the line and newline, the editor retains the line and rings the bell. It also rings the bell when input cannot fit.

## Design choices and trade-offs

The editor uses fixed-capacity line and completed-input buffers. A multibyte character that cannot fit is discarded. Random availability and network and neural-network devices depend on target or feature gates.
