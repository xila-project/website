The `bootsplash` crate provides the startup brand logo animation displayed while the operating system boots. It lives in the Core repository under `libraries/bootsplash/` and is exposed by the `xila` facade crate when the `bootsplash` feature is enabled.

## Context

During early system boot, Xila displays an animated bootsplash on the screen while storage, devices, and background services initialize. The `bootsplash` crate encapsulates the choreography, timing, and LVGL animation callbacks, providing a clean start and stop lifecycle for runtime initialization.

## How it works

### Animation sequence and geometry

The brand logo consists of a central square and four arms:

- Top-left (child index 0, clockwise rank 0, direction `(-1, -1)`)
- Top-right (child index 3, clockwise rank 1, direction `(1, -1)`)
- Bottom-right (child index 2, clockwise rank 2, direction `(1, 1)`)
- Bottom-left (child index 1, clockwise rank 3, direction `(-1, 1)`)

The animation runs in two distinct phases:

1. Intro phase (`timeline::INTRO`, 840 ms total):
   - The central square fades in from opacity 0 to 255 over 240 ms (`SQUARE_FADE`).
   - Each arm slides inward along its diagonal into place, one after the other in clockwise order.
   - Arm animation constants: `ARM_DELAY` 150 ms, `ARM_STAGGER` 100 ms, `ARM_DURATION` 450 ms.
   - The intro concludes exactly on the static rest pose of the brand symbol.
2. Loop phase (`timeline::PERIOD` 1600 ms, `PULSE` 800 ms):
   - A ripple runs clockwise around the symbol.
   - One arm at a time glides outward along its diagonal, briefly widening separation (opacity drops to `PULSE_OPACITY` 180), and returns.
   - The next arm clockwise starts halfway through the previous pulse.
   - The arms return to their rest positions between pulses; the symbol is never rotated or recolored.

### Lifecycle management

The <HostReference crate="bootsplash" kind="struct" symbol="Bootsplash" /> struct controls animation creation and teardown:

- `Bootsplash::new(graphics_manager)`:
  Acquires the graphics manager lock.
  Retrieves screen dimensions, computes the logo scaling factor (`Logo::get_factor(screen_size.scale(0.3)).max(1)`), and instantiates `Logo`.
  Centers the logo on the active screen (`lv_align_t_LV_ALIGN_CENTER`).
  Initializes an LVGL animation (`lv_anim_t`) with `intro_callback`, starting the intro timeline.
  When the intro completes (`intro_completed`), transitions to `first_cycle_callback`, then `cycle_callback` which loops indefinitely until stopped.
- `Bootsplash::stop(self, graphics_manager)`:
  Acquires the graphics manager lock.
  Deletes all registered callbacks (`intro_callback`, `first_cycle_callback`, `cycle_callback`) from the logo object via `lv_anim_delete`.

The following diagram shows the animation state transitions from startup initialization to the looping ripple and final stop:

```mermaid
stateDiagram-v2
    [*] --> Intro: Bootsplash::new
    state Intro {
        [*] --> SquareFade: Center square fades in (240 ms)
        SquareFade --> ArmsSlide: Arms slide inward clockwise (600 ms)
    }
    Intro --> FirstCycle: intro_completed
    FirstCycle --> LoopingRipple: first_cycle_completed
    LoopingRipple --> LoopingRipple: Clockwise arm pulses (1600 ms period)
    LoopingRipple --> [*]: Bootsplash::stop
```

`Bootsplash::new` begins the intro phase, fading the central square before sliding each arm inward clockwise. Once complete, it enters a continuous loop where each arm pulses outward in turn. When the desktop shell or graphical user interface is ready, calling `Bootsplash::stop` deletes the active animations and dismisses the bootsplash.

## Design choices and trade-offs

- Dedicated animation crate: Isolates LVGL C ABI animation descriptors and unsafe C callbacks from general shell and graphics components.
- Responsive geometric scaling: Automatically adapts logo size to 30% of the screen dimension, ensuring consistent presentation across different display resolutions.
- Deterministic timeline: Animation progress uses fixed-point mathematical functions (`ArmState`), allowing unit testing without a display server.

## Limits

- Requires the `graphics` subsystem and an initialized display driver.
- Animation choreography is hard-coded to the four-arm brand logo layout and does not expose a general-purpose animation timeline API.
