The `bootsplash` crate provides the startup brand logo animation displayed while the operating system boots. It lives in the Core repository under `libraries/bootsplash/`. The `xila` facade crate exposes it when the `bootsplash` feature is enabled.

## Context

During early boot, Xila displays an animated logo on the screen while storage, devices, and background services initialize. The `bootsplash` crate contains the animation choreography, timing, and LVGL callbacks. It provides a start and stop lifecycle for runtime initialization.

## How it works

### Animation sequence and geometry

The brand logo consists of a central square and four arms:

- Top-left (child index 0, clockwise rank 0, direction `(-1, -1)`)
- Top-right (child index 3, clockwise rank 1, direction `(1, -1)`)
- Bottom-right (child index 2, clockwise rank 2, direction `(1, 1)`)
- Bottom-left (child index 1, clockwise rank 3, direction `(-1, 1)`)

The animation runs in two phases:

1. Intro phase (`timeline::INTRO`, 900 ms total):
   - The central square fades in from opacity 0 to 255 over 240 ms (`SQUARE_FADE`).
   - Each arm slides inward along its diagonal into place, one after the other in clockwise order.
   - Arm animation constants: `ARM_DELAY` 150 ms, `ARM_STAGGER` 100 ms, `ARM_DURATION` 450 ms.
   - The intro concludes exactly on the static rest pose of the brand symbol.
2. Loop phase (`timeline::PERIOD` 1600 ms, `PULSE` 800 ms):
   - A ripple runs clockwise around the symbol.
   - One arm at a time glides outward along its diagonal, briefly widening the separation, and returns. During the pulse, the opacity drops to `PULSE_OPACITY` (180).
   - The next arm clockwise starts halfway through the previous pulse.
   - The arms return to their rest positions between pulses. The symbol is never rotated or recolored.

### Lifecycle management

The <Api path="bootsplash::Bootsplash" /> struct controls animation creation and teardown:

- `Bootsplash::new(graphics_manager)` acquires the graphics manager lock. It retrieves the screen dimensions and computes the logo scaling factor (`Logo::get_factor(screen_size.scale(0.3)).max(1)`). It instantiates `Logo` and centers it on the active screen (`lv_align_t_LV_ALIGN_CENTER`). It initializes an LVGL animation (`lv_anim_t`) with `intro_callback` and starts the intro timeline. When the intro completes (`intro_completed`), it transitions to `first_cycle_callback` and then to `cycle_callback`. `cycle_callback` loops until stopped.
- `Bootsplash::stop(self, graphics_manager)` acquires the graphics manager lock. It deletes all registered callbacks (`intro_callback`, `first_cycle_callback`, `cycle_callback`) from the logo object via `lv_anim_delete`.

`Bootsplash::new` begins the intro phase. The central square fades in, then each arm slides inward in clockwise order. When the intro completes, the animation enters a loop in which each arm pulses outward in turn. When the desktop shell or graphical user interface is ready, `Bootsplash::stop` deletes the active animations and dismisses the bootsplash.

## Design choices and trade-offs

- Dedicated animation crate: The crate isolates LVGL C ABI animation descriptors and unsafe C callbacks from general shell and graphics components.
- Responsive geometric scaling: The logo scales to 30% of the screen dimension. The presentation stays consistent across display resolutions.
- Deterministic timeline: Animation progress uses fixed-point mathematics (`ArmState`). Unit tests can run without a display server.

## Limits

- Requires the `graphics` subsystem and an initialized display driver.
- Animation choreography is hard-coded to the four-arm brand logo layout and does not expose a general-purpose animation timeline API.
