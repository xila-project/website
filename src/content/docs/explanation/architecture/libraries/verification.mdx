The package manager's `xila-package-verification` library supplies `no_std` SHA-256 and Ed25519 primitives for checking content and signatures.

## Context

Package tools and the Applications installer need the same cryptographic checks without a host file system. The library supplies the primitives. Callers decide which key to trust and which bytes to verify.

## How it works

A content verifier hashes bytes incrementally. It checks the expected length and the digest. A public key verifies an Ed25519 signature over a message. The package manifest and reader code define the signed message, and they check the file inventory with these primitives.

## Design choices and trade-offs

The library supports incremental hashing and `no_std` consumers. A valid signature alone does not authorize a developer key. Repository metadata or a directly trusted key makes that decision.
