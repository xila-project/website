The `package` executable in the Applications repository installs packages into the virtual file system (VFS) of Xila. It accepts local packages and packages from configured repositories.

## Context

The executable connects repository metadata and package verification to VFS storage. Its desktop counterpart, `xila-package`, builds and signs packages.

## How it works

Repository installation verifies signed metadata with the configured root key. It then checks the developer key, the package signature, and the payload hashes. Installation also checks that the package targets `wasm32-wasip1` and that its `xila_version` is compatible with the running Xila. A local archive goes through the registry entry that pins it: the installer looks up the archive's name and version in the configured repositories, and that entry must match the archive's SHA-256 and size. The `--public-key` option verifies a local archive with a given key instead, for offline sideloading. The `--allow-untrusted` option skips publisher authentication for a local package but keeps the integrity checks.

The installer reads 512-byte TAR blocks and writes them to a quarantine directory. After verification, it moves the bundle to `/applications/bundles/<identifier>/`. The commands `install`, `upgrade`, `remove`, `recover`, `list`, `info`, and `search` manage packages. The `repository` commands add, list, and remove configured repositories. See [Package management](/explanation/package-management/) for the trust chain.

## Design choices and trade-offs

Streaming avoids holding a complete package in memory. Staging keeps a failed verification from being promoted as an installed bundle. A local key override does not add that key to system trust.

## Limits

Root and the members of the `administrator` group may change packages and repositories. Package changes run as crash-consistent transactions, journaled in `/configuration/system/packages/transaction.json`; `package recover` finishes or undoes an interrupted operation. The Wasm runtime hashes each installed package executable against the installed manifest before compiling it. It does not verify a signature at launch. Repository index expiry is not checked without a trustworthy clock.
