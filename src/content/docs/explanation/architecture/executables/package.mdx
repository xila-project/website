The `package` executable in the Applications repository installs packages into the virtual file system (VFS) of Xila. It accepts local packages and packages from configured repositories.

## Context

The executable connects repository metadata and package verification to VFS storage. Its desktop counterpart, `xila-package`, builds and signs packages.

## How it works

Repository installation verifies signed metadata with the configured root key. It then checks the developer key, the package signature, and the payload hashes. Local installation trusts `/configuration/system/packages/trusted.pub` or a key given with `--public-key`. The `--allow-untrusted` option skips publisher authentication for a local package but keeps the integrity checks.

The installer reads 512-byte TAR blocks and writes them to a quarantine directory. After verification, it moves the bundle to `/applications/bundles/<identifier>/`. `package list` shows the installed bundles. The repository commands add, list, and remove configured repositories. See [Package management](/explanation/package-management/) for the trust chain.

## Design choices and trade-offs

Streaming avoids holding a complete package in memory. Staging keeps a failed verification from being promoted as an installed bundle. A local key override does not add that key to system trust.

## Limits

System-wide installation requires a root task. The installer has no upgrade, uninstall, or power-loss recovery journal. It does not verify a signature at launch. It does not check repository index expiry without a trustworthy clock.
