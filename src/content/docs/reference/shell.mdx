This page is the reference for the command syntax, execution rules, built-in commands, and resource limits of Xila's command-line shell (<CodeReference repo="applications" path="executables/shell/command_line"><code>command_line_shell</code> crate</CodeReference>, <CodeReference repo="applications" path="executables/shell/command_line/src/commands/mod.rs" />).

## Invocation

The shell executable accepts the following invocation modes:

| Invocation             | Arguments          | Description                                                                                             |
| ---------------------- | ------------------ | ------------------------------------------------------------------------------------------------------- |
| Interactive mode       | None               | Authenticates the user if unauthenticated and presents an interactive prompt (`user@host:directory$ `). |
| Command string         | `-c "COMMAND"`     | Parses and executes the provided command string, including pipelines and redirections.                  |
| Script file            | `-s PATH`          | Reads and executes lines sequentially from a file in the virtual file system (VFS).                     |
| Programmatic arguments | `COMMAND [ARG]...` | Executes the command and arguments literally without re-tokenizing or performing shell expansion.       |

Nested script executions track the recursion depth in the `XILA_SHELL_DEPTH` environment variable. An invocation that exceeds the maximum depth of four stops with exit status 2.

## Interactive line editing

In interactive mode, the shell reads keys from standard input in raw mode and edits the line itself. The graphical [Terminal](/explanation/architecture/executables/terminal/) forwards its keys to the shell editor and keeps the cursor in its own command field.

| Key         | Action                                                                                               |
| ----------- | ---------------------------------------------------------------------------------------------------- |
| Left, Right | Move the cursor one character                                                                        |
| Home, End   | Move the cursor to the start or end of the line                                                      |
| Backspace   | Delete the character before the cursor                                                               |
| Delete      | Delete the character under the cursor                                                                |
| Ctrl+A      | Move the cursor to the start of the line                                                             |
| Ctrl+E      | Move the cursor to the end of the line                                                               |
| Ctrl+U      | Delete the text before the cursor                                                                    |
| Ctrl+K      | Delete the text after the cursor                                                                     |
| Ctrl+W      | Delete the preceding word                                                                            |
| Ctrl+D      | Delete the character under the cursor; end input on an empty line                                    |
| Ctrl+C      | Cancel the line                                                                                      |
| Up, Down    | Recall the previous or next history entry; Down past the newest entry restores the line being edited |
| Tab         | Complete the word; see [Tab completion](#tab-completion)                                             |
| Enter       | Submit the line                                                                                      |

Arrow, Home, End and Delete keys arrive as CSI escape sequences (`ESC [ A` through `ESC [ D`, `ESC [ H` or `ESC [ 1~` or `ESC [ 7~`, `ESC [ F` or `ESC [ 4~` or `ESC [ 8~`, `ESC [ 3~`). Input that is not valid UTF-8 is refused with a bell: the editing keys still work on the refused line, and Enter refuses it with an invalid UTF-8 message and exit status 2 instead of running it.

The interactive editor accepts at most 512 bytes per command (`MAXIMUM_LINE_BYTES`). The shell discards an overlong command on Enter with exit status 2. Script and `-c` source lines keep the 4,096-byte limit of the [limits table](#limits).

### History

Up and Down recall commands from the current session. History holds eight commands by default. Set the `XILA_SHELL_HISTORY_CAPACITY` environment variable before launching the shell to select a capacity from 0 to 32; a capacity of 0 disables history. The shell omits blank lines and consecutive duplicate commands from history.

### Display width and the 80-column assumption

The shell redraws the edited line with relative cursor movement (carriage return, `CSI n A`, `CSI J`, `CSI n C`) computed from the prompt width, the line width and an assumed 80-column terminal, so a line that wraps past the bottom row still redraws correctly once the screen scrolls. No device control reports the terminal size yet, so 80 columns is assumed.

Display width is measured per character: East Asian Wide and Fullwidth characters take two columns and combining marks take none. The widths come from a small built-in table that covers the common CJK ideograph and radical ranges, Hiragana, Katakana, Bopomofo, Hangul, the Yi script, CJK compatibility ideographs and forms, fullwidth forms and signs, the East Asian Wide subranges of the emoji blocks, and the combining diacritical marks. Text presentation emoji (for example U+1F321) are Neutral and take one column. Rarer wide or combining characters, for example from the miscellaneous symbols, Tangut, Khitan or extended Kana blocks, or other combining blocks such as Devanagari or Hebrew marks, count as one column.

## Tab completion

Press Tab to complete the command name or the current component of a path:

- **Command name**: at the start of a command, Tab searches the built-in commands (including `sudo`) and the executable entries in the directories of the `Paths` environment variable.
- **Path**: otherwise, Tab searches the named directory, or the current directory for a relative path.

One match completes the word. If several matches share a prefix, the first Tab fills in that prefix, replacing only the text before the cursor, as readline does. Press Tab again to list up to 12 matches; the list also reports how many further matches were collected. If nothing matches, the shell rings the bell and leaves the line as typed. Tab is ignored inside a comment, on a variable (`$NAME`, `$?`) or inside an operator. The graphical terminal also has a completion button beside Send.

Each search is bounded: 150 milliseconds, 16 search directories, 256 directory entries in total, 64 matches and 4,096 bytes of match text. If a search reaches one of these limits, the listing can be incomplete and the shell leaves the word as typed.

## Command composition

The shell parser splits input lines into pipeline stages and conditional execution chains using standard shell operators:

| Operator        | Syntax             | Description                                                                                  |
| --------------- | ------------------ | -------------------------------------------------------------------------------------------- |
| Pipe            | `stage1 \| stage2` | Connects stdout of `stage1` to stdin of `stage2` through an unnamed in-memory VFS pipe.      |
| Logical AND     | `cmd1 && cmd2`     | Executes `cmd2` only if `cmd1` terminates with exit status 0.                                |
| Logical OR      | `cmd1 \|\| cmd2`   | Executes `cmd2` only if `cmd1` terminates with a non-zero exit status.                       |
| Sequential      | `cmd1 ; cmd2`      | Executes `cmd1`, followed by `cmd2` regardless of exit status.                               |
| Background      | `cmd &`            | Spawns the pipeline as a detached task with stdin redirected to `/devices/standard_io/null`. |
| Input redirect  | `< PATH`           | Redirects standard input from the file at `PATH`.                                            |
| Output redirect | `> PATH`           | Truncates and writes standard output to the file at `PATH`.                                  |
| Output append   | `>> PATH`          | Appends standard output to the file at `PATH`.                                               |
| Error redirect  | `2> PATH`          | Truncates and writes standard error to the file at `PATH`.                                   |
| Error append    | `2>> PATH`         | Appends standard error to the file at `PATH`.                                                |
| Comment         | `# TEXT`           | Ignores all characters from `#` to the end of the line when `#` begins a word.               |

## Variable expansion

The shell expands parameters and status values before command execution:

- `$NAME` or `${NAME}`: the value of the task environment variable `NAME`. An unset variable expands to an empty string.
- `$?`: the decimal exit status of the most recent foreground command.
- Double quotes (`"..."`): keep literal whitespace and enable variable expansion and the escape sequences `\$`, `\"`, and `\\`.
- Single quotes (`'...'`): keep all enclosed characters literal, without variable expansion or escape sequences.
- Command substitution: `$(...)` and backticks are not supported and cause a syntax error.

## Resolution

When a command line does not match an internal built-in, the shell resolves an external executable target:

1. **Path contains `/`**: a command with any forward slash is a path. Absolute paths (`/applications/executables/...`) execute directly. The shell resolves relative paths against the task's `Current_directory` environment variable.
2. **Path contains no `/`**: the shell reads the colon-separated directory list in the `Paths` environment variable (for example, `/applications/executables`). It scans each directory in order and executes the first matching executable file.
3. **Execution dispatch**: the shell passes the resolved path to <Api path="executable::execute" />. The function verifies permissions and spawns the target task. If no command matches, the command fails with exit status 127.

The shell first checks its built-in lookup table. A command that contains a forward slash is a path: absolute paths run directly, and relative paths are joined with the `Current_directory` environment variable. A command without a slash is looked up in the colon-separated directories of the `Paths` environment variable; the first match wins and is passed to `executable::execute`. When nothing matches, the command fails with exit status 127.

## Limits

The shell enforces these resource limits:

| Limit                | Value                                                                                 | Description                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Source line          | 4,096 bytes                                                                           | Maximum raw byte length of a script or `-c` command line (`MAX_INPUT_BYTES`).                            |
| Interactive line     | 512 bytes                                                                             | Maximum byte length of one edited interactive command (`MAXIMUM_LINE_BYTES`).                            |
| History entries      | 8 by default, 0 to 32                                                                 | Commands recalled with Up and Down; set `XILA_SHELL_HISTORY_CAPACITY` before launching the shell.        |
| Token count          | 256                                                                                   | Maximum number of parsed tokens per command line (`MAX_TOKENS`).                                         |
| Expansion buffer     | 8,192 bytes                                                                           | Maximum length of a command line after environment variable and status expansion (`MAX_EXPANDED_BYTES`). |
| Pipeline buffer      | 512 bytes                                                                             | Capacity of the unnamed in-memory pipe ring buffer connecting pipeline stages (`PIPE_BYTES`).            |
| Background tasks     | 8                                                                                     | Maximum concurrent background jobs running simultaneously (`MAX_BACKGROUND_JOBS`).                       |
| Nesting depth        | 4                                                                                     | Maximum recursion depth for nested shell script invocations (`MAX_SHELL_DEPTH`).                         |
| Tree traversal depth | 32                                                                                    | Maximum recursion depth for `tree` and `find` commands.                                                  |
| Completion search    | 150 ms, 16 directories, 256 entries, 64 matches, 4,096 bytes of match text, 12 listed | Bounds of one Tab completion search.                                                                     |
| Terminal width       | 80 columns                                                                            | Assumed columns for redrawing the interactive line; no device control reports the terminal size yet.     |

## Errors

Commands and script invocations terminate with specific numeric status codes:

| Status code | Cause                 | Description                                                                                               |
| ----------- | --------------------- | --------------------------------------------------------------------------------------------------------- |
| `0`         | Success               | Command completed successfully.                                                                           |
| `1`         | Command error         | Built-in command reported an execution failure, stream flush failed, or background job limit reached.     |
| `2`         | Syntax or usage error | Command line exceeded length limits, unclosed quotes, invalid expansion syntax, or script file I/O error. |
| `127`       | Command not found     | Command could not be resolved in built-in registry, explicit path, or `Paths` directory search.           |
