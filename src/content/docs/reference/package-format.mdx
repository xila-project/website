The experimental package format describes the `.xpk` archive and its signed inventory. The source of truth is the <CodeReference repo="package_manager" path="crates/manifest/src/lib.rs">manifest implementation</CodeReference> and its <CodeReference repo="package_manager" path="schemas/package-manifest.schema.json">JSON schema</CodeReference>.

## Archive

The writer produces an uncompressed USTAR archive of ordinary files. `.xila/manifest.json` comes first. When the package is signed, `.xila/manifest.sig` follows. Payload files come last, in manifest order. The writer uses zero timestamps, zero owner IDs, and mode `0644`. The signature is 64 raw Ed25519 bytes. Unsigned packages omit the signature.

## Manifest

| Field                       | Meaning                                                                                       |
| --------------------------- | --------------------------------------------------------------------------------------------- |
| `$schema`                   | Optional editor schema URL.                                                                   |
| `format_version`            | Format version, `2`.                                                                          |
| `name`, `version`, `target` | Reverse-DNS package name, version and target. The name has at least three components.         |
| `xila_version`              | Minimum Xila release as `major.minor`.                                                        |
| `capabilities`              | Requested capability strings.                                                                 |
| `files`                     | Ordered inventory of `path`, `size` and lowercase hexadecimal `sha256`.                       |
| `application`               | Required. Null or an object with `entrypoint`, `display_name`, `icon` and `show_in_launcher`. |
| `metadata`                  | Optional. Null or an object with `summary`, `license`, `source` and optional `homepage`.      |

Legacy two-component `xila.<name>` names stay valid until Xila's own packages migrate. The installer rejects a package when `xila_version` is not compatible with the running Xila release. Before Xila 1.0, the major and minor versions must be equal. From Xila 1.0, the major versions must be equal and the running minor version must be at least the declared one. Patch versions are ignored.

A bundle-local entrypoint and a nonempty icon must name files in the inventory. A system entrypoint can instead refer to an existing executable under `/system/executables/` or `/applications/executables/`.

## Signature

The developer signs the exact stored manifest bytes with Ed25519. The signed message is the ASCII domain `XILA-PACKAGE-MANIFEST-V1`, one zero byte, the manifest byte length as a little-endian 32-bit integer, and the manifest bytes. SHA-256 digests cover the payload bytes. See the <CodeReference repo="package_manager" path="crates/bundle/src/lib.rs">bundle implementation</CodeReference> and <CodeReference repo="package_manager" path="crates/reader/src/stream.rs">streaming reader</CodeReference>.

## Limits

- A manifest is at most 65,536 bytes. It lists at most 128 files and 256 MiB of total payload.
- Paths are relative and at most 200 bytes long. They cannot contain empty, `.`, or `..` segments, backslashes, control characters, or the reserved `.xila/` prefix. The USTAR writer has a stricter 99-byte ASCII path limit.
- Names are at most 96 bytes. Versions and targets are at most 64 bytes. There are at most 32 capabilities, each at most 64 bytes.
- The streaming reader consumes 512-byte TAR blocks. It retains bounded manifest data while processing payloads.
