## Cargo features

Guest crates depend on `xila-wasm` with `default-features = false` to omit the host Wasmi runtime:

| Feature         | Default | Effect                                                                     |
| --------------- | ------- | -------------------------------------------------------------------------- |
| `default_guest` | No      | Enables `guest`, `graphics`, `c_bindings`, and `memory_32`                 |
| `guest`         | No      | Enables the guest module, core error types, and `fd_control`               |
| `graphics`      | No      | Enables generated LVGL guest wrappers and geometry helpers                 |
| `c_bindings`    | No      | Exports `extern "C"` functions and generates `xila_graphics.h`             |
| `memory_32`     | Yes     | Configures 32-bit guest pointer width (`usize = u32`)                      |
| `memory_64`     | No      | Configures 64-bit guest pointer width (`usize = u64`)                      |
| `host`          | Yes     | Compiles the host Wasmi interpreter. Host only; do not enable it in guests |

## Host import namespaces

Guest modules interact with Xila through two host import namespaces:

- `wasi_snapshot_preview1`: Standard WASI Preview 1 system calls for I/O, file systems, clocks, and Xila's custom descriptor control function `fd_control`.
- `host`: The graphics multiplexer import `xila_graphics_call`.

## WASI Preview 1 imports

The host runtime provides the following system calls in the `wasi_snapshot_preview1` namespace (<CodeReference repo="applications" path="executables/wasm/src/host/wasi/register.rs" />):

| Domain                    | Imported functions                                                                                                                      | Description                                                                          |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Arguments and environment | `args_get`, `args_sizes_get`, `environ_get`, `environ_sizes_get`                                                                        | Reads command-line arguments and environment variables                               |
| Descriptor I/O            | `fd_read`, `fd_write`, `fd_close`, `fd_seek`, `fd_fdstat_get`, `fd_filestat_get`, `fd_readdir`, `fd_prestat_get`, `fd_prestat_dir_name` | Performs file, directory, pipe, and device I/O                                       |
| Device control            | `fd_control`                                                                                                                            | Sends typed control commands to virtual file system (VFS) character devices          |
| File system paths         | `path_open`, `path_create_directory`, `path_filestat_get`, `path_readlink`, `path_symlink`, `path_unlink_file`                          | Resolves and manipulates file paths relative to directory descriptors                |
| Clocks and randomness     | `clock_res_get`, `clock_time_get`, `random_get`                                                                                         | Queries monotonic and realtime clocks or reads cryptographically secure random bytes |
| Process and scheduling    | `proc_exit`, `sched_yield`, `poll_oneoff`                                                                                               | Terminates execution, yields to the scheduler, or waits for clock timers             |

## Device control

The <Api api="guest" path="wasm::fd_control" /> function sends typed control commands to VFS character devices, such as audio playback devices or serial interfaces:

```rust
pub unsafe fn fd_control(
    fd: i32,
    command: u32,
    input: *const u8,
    input_length: u32,
    output: *mut u8,
    output_length: u32,
) -> i32
```

The host validates four constraints on every call:

1. Write authorization: a command with the write direction bit set requires a descriptor that was opened with write access.
2. Alignment: Non-empty `input` and `output` pointers must be 16-byte aligned.
3. Payload size: Neither `input_length` nor `output_length` may exceed 256 bytes.
4. Non-overlapping buffers: Input and output byte ranges in guest memory must not overlap.

## Graphics functions

When compiled with the `graphics` feature, `xila-wasm` provides safe wrappers around the LVGL graphics subsystem:

- Constructors: <Api api="guest" path="wasm::window_create" />, <Api api="guest" path="wasm::button_create" />, <Api api="guest" path="wasm::label_create" />.
- Destruction: <Api api="guest" path="wasm::object_delete" /> releases the native widget and frees the handle slot.
- Types: <Api api="guest" path="wasm::ObjectHandle" />, <Api api="guest" path="wasm::Color" />, <Api api="guest" path="wasm::Point" />, <Api api="guest" path="wasm::Area" />, <Api api="guest" path="wasm::EventCode" />.

## Limits

| Resource                  | Limit                | Traced code location                                                     |
| ------------------------- | -------------------- | ------------------------------------------------------------------------ |
| Control command payload   | 256 bytes            | `MAX_CONTROL_PAYLOAD` in `executables/wasm/src/host/wasi/file.rs`        |
| Control command alignment | 16 bytes             | `CONTROL_PAYLOAD_ALIGNMENT` in `executables/wasm/src/host/wasi/file.rs`  |
| Instruction fuel quantum  | 100,000 instructions | `instruction_limit` default in `executables/wasm/src/host/main.rs`       |
| Standard string length    | 1,024 bytes          | `MAX_STRING_BYTES` in `subsystems/graphics/src/call/marshal.rs` (Core)   |
| Textarea string length    | 4,097 bytes          | `MAX_TEXTAREA_BYTES` in `subsystems/graphics/src/call/marshal.rs` (Core) |
| Clock subscriptions       | 64                   | `MAX_SUBSCRIPTIONS` in `executables/wasm/src/host/wasi/poll_memory.rs`   |

## Errors

Error types returned by guest APIs:

- <Api api="guest" path="wasm::Error" />: Standard guest error type.
- <Api api="guest" path="wasm::Result" />: Convenience type alias for `Result<T, Error>`.
- Graphics status codes: a nonzero `i32` return value from a graphics operation indicates failure, for example invalid memory, an invalid handle, or resource exhaustion.
