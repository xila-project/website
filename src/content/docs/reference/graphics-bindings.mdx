The graphics bindings connect WebAssembly (Wasm) guest applications to the LVGL graphics subsystem. The interface is generated by `xila-graphics-bindgen` (<CodeReference path="subsystems/graphics/bindings_generator" />) and dispatched by `xila-wasm` (<CodeReference repo="applications" path="executables/wasm/src/host/graphics/mod.rs" />).

## Host import ABI

The host registers a single multiplexer import in the `"host"` namespace (<CodeReference repo="applications" path="executables/wasm/src/host/graphics/wasmi.rs" />):

```rust
fn xila_graphics_call(
    function: i32,
    a: usize,
    b: usize,
    c: usize,
    d: usize,
    e: usize,
    f: usize,
    g: usize,
    count: i32,
    result: usize,
) -> i32
```

The function receives a numeric call identifier, up to seven word arguments (`a` through `g`), an argument count, and an optional guest memory address for return data.

## Status codes

Every graphics call returns a numeric status code (<CodeReference path="subsystems/graphics/src/call/error.rs" />):

| Code | Name                    | Description                                                              |
| ---- | ----------------------- | ------------------------------------------------------------------------ |
| 0    | Success                 | Operation completed successfully                                         |
| 1    | `InvalidArgumentsCount` | Argument count does not match the catalog signature                      |
| 2    | `InvalidMemory`         | Pointer or slice exceeds guest linear memory bounds                      |
| 3    | `Unavailable`           | Graphics capability is not present in the execution context              |
| 4    | `Unsupported`           | Call identifier is unmapped or unsupported                               |
| 5    | `InvalidHandle`         | Object handle is unrecognized, unallocated, or previously deleted        |
| 6    | `ResourceLimit`         | Operation exceeds capacity limits for objects, canvas pixels, or buffers |
| 7    | `InvalidValue`          | Argument value is out of bounds or represents an invalid enum state      |
| 8    | `NativeFailure`         | Underlying LVGL graphics operation returned failure                      |

## Custom helpers

The graphics interface provides custom extensions assigned call identifiers starting at `0xf000`:

- `grid_fr` (`0xf006`): Encodes fractional grid track units.
- Semantic theme and font selectors (`0xf007` through `0xf00e`): Select host-owned fonts and theme surfaces without exposing raw host pointers.
- Indexed canvas (`indexed_canvas_create`, `indexed_canvas_set_pixels`): Allocates host-owned pixel buffers and copies color palettes from guest memory.
- Pointer events (`window_pop_pointer_event`): Retrieves pointer event coordinates relative to content areas.
- System file picker (`0xf02d` through `0xf030`): Creates and manages system open/save file dialogs.

## Unsupported operations

The guest API deliberately excludes operations that cannot be safely sandboxed:

- Direct pointer callbacks into guest code.
- Unrestricted native pointers to `lv_style_t` or `lv_font_t`.
- Retained pointers to mutable guest memory.
- Raw file path access bypassing the virtual file system (VFS).
- Unadapted widgets such as Table, Menu, and Messagebox.

Attempting to call an unsupported function identifier returns status code 4 (`Unsupported`).

## Limits

The graphics call executor in Core enforces the following resource boundaries (<CodeReference path="subsystems/graphics/src/call/marshal.rs" />):

| Resource                         | Limit           | Source                                              |
| -------------------------------- | --------------- | --------------------------------------------------- |
| Grid tracks per axis             | 32 tracks       | `MAX_GRID_TRACKS_PER_AXIS` in `marshal.rs`          |
| Retained grid descriptors per VM | 512 descriptors | `MAX_GRID_TRACKS_PER_VM` in `state.rs`              |
| Canvas pixels per VM             | 65,536 pixels   | `MAX_CANVAS_PIXELS` in `canvas.rs`                  |
| Control range value              | 1,000,000       | `MAX_RANGE_VALUE` in `handlers.rs`                  |
| String length                    | 1,024 bytes     | `MAX_STRING_BYTES` in `marshal.rs`                  |
| Textarea text length             | 4,097 bytes     | `MAX_TEXTAREA_BYTES` in `marshal.rs`                |
| Widget options count             | 64 options      | `MAX_WIDGET_OPTIONS` in `marshal.rs`                |
| Widget options string length     | 1,024 bytes     | `MAX_WIDGET_OPTIONS_BYTES` in `marshal.rs`          |
| Infinite roller options length   | 512 bytes       | `MAX_ROLLER_INFINITE_OPTIONS_BYTES` in `marshal.rs` |
| Retained options per VM          | 8,192 bytes     | `MAX_WIDGET_OPTIONS_BYTES_PER_VM` in `marshal.rs`   |
| Button-map items                 | 64 entries      | `MAX_MAP_ENTRIES` in `marshal.rs`                   |
| Retained button-map storage      | 8,192 bytes     | `MAX_MAP_BYTES` in `marshal.rs`                     |
| Calendar highlighted dates       | 32 dates        | `dispatch.rs`                                       |
| Chart series per chart           | 8 series        | `dispatch.rs`                                       |
| Chart values per series          | 128 points      | `dispatch.rs`                                       |
| Line points per widget           | 128 points      | `dispatch.rs`                                       |
