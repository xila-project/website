The host API documentation is the rustdoc of the Rust crates in the Core workspace, for the `x86_64-unknown-linux-gnu` target. It starts at the `xila` façade crate. Each crate, module, type, trait and function has its own page under `/api/host/`. The site search finds the items by name.

## Cargo features

The `xila` crate in <CodeReference path="core/Cargo.toml" /> is a `#![no_std]` façade (<CodeReference path="core/src/lib.rs" />). It re-exports Core workspace subsystems and libraries under unified names. These modules, among others, are always available without optional features: `authentication`, `executable`, `file_system`, `internationalization` (via `embedded-i18n`), `little_fs`, `log`, `memory`, `shared`, `synchronization`, `task`, `time`, `users`, and `virtual_file_system`.

| Feature                       | Default | Effect                                                                                                 |
| ----------------------------- | ------- | ------------------------------------------------------------------------------------------------------ |
| `network`                     | Yes     | Re-exports <Api path="network" /> and enables network support in `executable`                          |
| `audio`                       | No      | Re-exports <Api path="audio" /> (PCM stream contracts and software mixer)                              |
| `bootsplash`                  | No      | Re-exports <Api path="bootsplash" /> (startup splash screen animation)                                 |
| `executable_building`         | No      | Enables executable building utilities in <Api path="executable" />                                     |
| `graphics`                    | No      | Re-exports <Api path="graphics" /> and enables graphics support in `executable`                        |
| `graphics_rendering_rgb565`   | No      | Enables `graphics` and configures 16-bit RGB565 color depth rendering                                  |
| `graphics_rendering_xrgb8888` | No      | Enables `graphics` and configures 32-bit XRGB8888 color depth rendering                                |
| `neural_network`              | No      | Re-exports <Api path="neural_network" /> and <Api path="drivers_neural_network" />                     |
| `native-dev`                  | No      | Enables raw ELF native executables in `executable` (the platform must also register the native format) |
| `task_metrics`                | No      | Enables task and executor activity metrics in <Api path="task" />                                      |

## Generation

Core's `docs:host` mise task generates the host Rustdoc. Run `mise run docs:host -- --no-deps`; the task is defined in <CodeReference path="mise.toml" />. It invokes `cargo doc --workspace` for the target `x86_64-unknown-linux-gnu` with the features `xila/graphics`, `xila/graphics_rendering_xrgb8888`, `xila/audio`, `xila/neural_network`, `xila/bootsplash`, and `xila-testing/graphics`.

When `CARGO_TARGET_DIR` is unset, Cargo writes the HTML output to `target/x86_64-unknown-linux-gnu/doc/xila/index.html`, relative to the Core repository root. In the website repository, `npm run docs:rustdoc` (or `mise run documentation:rustdoc`) runs this task with `--no-deps`. It stages the output in `public/api/host/`, adds to each page a script and a style sheet that show it in the frame page of the site (`/reference/api/`) under the site header, with the site colours, typeface and theme, and writes the API index `public/api/api-index.json`. The site build publishes them under `/api/`. See `scripts/build-rustdoc.mjs` and `mise.toml`.

For the complete list of development tasks, see [Development commands](/reference/development-commands/).
