This guide shows how to prepare and validate a change in Core.

## Before you begin

- Set up the [development environment](/how-to/setup-development/) and install Core's native build dependencies.
- Read [Core's contributor rules](https://github.com/xila-project/core/blob/main/AGENTS.md) and the rules in each repository you change.

## Steps

1. Make the change in the crate that owns the behavior, and update its tests and documentation when the change affects them.
2. Follow the [workspace dependency rules](https://github.com/xila-project/workspace/blob/main/AGENTS.md) for cross-repository Cargo dependencies: use `branch = "main"` and update the lockfile with `cargo update -p <crate>` when repinning.
3. In the Core repository root, check formatting in a host shell:

   ```sh
   mise run format:rust -- --check
   mise run format:toml -- --check
   ```

4. In the Core repository root, check host and guest targets, lint them, and test the workspace:

   ```sh
   mise run check:all
   mise run clippy:all
   mise run test:workspace
   ```

5. In the Core repository root, run `mise run localization:check` for localization changes and `mise run test:fonts` for font changes. Consult [Development commands](/reference/development-commands/) for focused tasks.
6. When the change crosses repository boundaries, also check integration in the affected repositories.
7. Review your diff and follow the affected repository's contribution and commit conventions.

## Verify the result

Each command exits successfully. The diff contains the intended source, tests and documentation. Core CI's required gate depends on the quality, verification, host, bare-metal, Xtensa, Wasm, ABI, localization and SDK jobs. Local host checks do not establish hardware correctness.
