This guide shows how to create, switch and permanently delete Xila disk images in the browser demonstration. Use it to manage test disks or to reset a corrupt disk.

## Before you begin

- Open the browser demonstration at [platforms.xila.dev](https://platforms.xila.dev/) or your local Trunk development server.
- A browser that supports the Origin Private File System (OPFS) and the Web Locks API.
- Back up any important files before deleting a disk.

:::caution[Deleting a disk causes irreversible data loss]
Removing a disk permanently deletes its OPFS file and all files, configuration, and accounts stored on that image.
:::

## Steps

### Create a new disk

1. Open the **Xila Help** sidebar panel located on the left edge of the browser demonstration.
2. In the disk actions toolbar below **Available disks**, click **New disk**.
3. When the browser confirmation dialog asks `Save and restart Xila using xila_YYYY-MM-DD.img?`, click **OK**.
4. The runtime stops active writes and commits pending changes to the current disk. It releases the Web Lock and reloads on the fresh disk image, initialized from the prebuilt seed.

### Switch between saved disks

1. In the **Xila Help** sidebar, locate the **Available disks** list.
2. Click the name of the target disk to select it. Disks currently open in other tabs are marked with `(open)`.
3. Click **Use selected disk**.
4. When prompted to confirm the restart, click **OK**. The runtime commits pending writes, records the selection in `localStorage`, and reloads.

### Remove an unused disk

:::caution[Permanent deletion]
A removed disk cannot be recovered. Ensure you select the intended image before confirming.
:::

1. In **Available disks**, click the disk you want to delete. The currently active disk cannot be deleted from its own tab.
2. Click **Remove**. If the button is disabled, the disk is either currently active or held by another open tab.
3. When the confirmation prompt asks `Permanently remove <name> and all files stored on it?`, click **OK**.
4. The disk manager acquires an exclusive lock on the image and removes the file from OPFS.

### Reset storage using browser developer tools

If a corrupt image prevents the interface from loading, clear the OPFS entry directly:

1. Close all open Xila tabs for the current origin.
2. Open a new tab on the same origin (for example, the site root).
3. Open the browser developer tools console and run:

```javascript
const root = await navigator.storage.getDirectory();
await root.removeEntry("xila_drive.img");
```

4. Alternatively, use the browser site settings to clear all stored data and cookies for the origin.

## Verify the result

1. Reopen the demonstration page.
2. Open the **Xila Help** sidebar.
3. Confirm that **Available disks** displays the expected disk list and that the target image was removed or loaded.
4. On a freshly created or reset disk, log in with the default administrator credentials:
   - **User name**: `administrator`
   - **Password**: (leave blank)

## Troubleshooting

| Symptom                                                    | Cause                                                                                              | Fix                                                                                   |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| The **Remove** button remains disabled.                    | The selected disk is active in this tab or holds a Web Lock in another tab.                        | Select an inactive disk, or close other browser tabs running Xila on the same origin. |
| The disk status displays `Browser storage is unavailable`. | The browser is in a private browsing mode that restricts OPFS, or storage permissions are blocked. | Use a standard browsing window with OPFS and Web Locks enabled.                       |
| Startup stops with a mount error.                          | The existing disk image was corrupted or modified outside Xila.                                    | Use the developer tools console command to remove the damaged disk and reload.        |
