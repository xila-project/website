This guide shows how to create a signed package with the desktop `xila-package` tool.

## Before you begin

- Install the <CodeReference repo="package_manager" path="crates/builder">package manager tool</CodeReference> and prepare a compiled WebAssembly (Wasm) guest application.
- A developer signing key: a raw 32-byte Ed25519 seed and its public key. Keep the seed outside the source directory.

## Steps

1. In a host shell in your working directory, initialize a source folder:

   ```sh
   xila-package bundle init ./weather example.xila.weather 1.0.0 wasm32-wasip1 --xila-version 0.1 --entrypoint executables/weather.wasm --display-name Weather --icon resources/icon.png
   ```

2. Place the compiled guest at `weather/executables/weather.wasm` and its icon at `weather/resources/icon.png`. Then review `weather/xila-package.json`.
3. In the same host shell, build and sign the bundle:

   ```sh
   xila-package bundle build ./weather ./Weather.app --signing-key ./signing/private.seed
   ```

4. In the same host shell, verify the bundle and make the package:

   ```sh
   xila-package bundle verify ./Weather.app --public-key ./signing/public.key
   xila-package bundle archive ./Weather.app ./Weather.xpk
   ```

The following diagram shows the artifacts of the four `bundle` commands and where the signing key is used.

</div>

`bundle init` creates the source folder with the editable `xila-package.json`. `bundle build` hashes every payload file and signs the manifest only when `--signing-key` is given; the thick arrow shows the developer seed signing the bundle. `bundle verify` checks the payload hashes and the signature against the trusted public key. `bundle archive` packs the validated bundle into the deterministic `.xpk` package.

## Verify the result

The commands succeed and `Weather.xpk` exists. Verification with the trusted public key checks the signed manifest and inventory.
