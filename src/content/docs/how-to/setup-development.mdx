This guide shows how to configure a local development environment for Xila using mise and Cargo. Use it to prepare the repositories for local builds, testing, and cross-repository development.

## Before you begin

- An x86_64 Linux development system (Debian or Ubuntu recommended).
- [Git](https://git-scm.com/) installed to clone repositories.
- [mise](https://mise.jdx.dev/) installed on your host system.
- Pinned toolchains (Rust, Node.js, and utilities) are installed automatically by mise when running tasks.
- Clone the three main repositories as siblings:

```sh
git clone https://github.com/xila-project/core.git
git clone https://github.com/xila-project/applications.git
git clone https://github.com/xila-project/platforms.git
```

## Steps

### Configure the Platforms repository

1. In the Platforms repository root, trust the mise configuration:

```sh
cd platforms
mise trust
```

2. Install native system packages for ALSA audio, Wayland, and X11:

```sh
mise bootstrap packages apply --manager apt
```

3. Install npm dependencies for font conversion:

```sh
npm ci
```

### Configure the Core repository

1. In the Core repository root, trust the mise configuration:

```sh
cd ../core
mise trust
```

2. Install native development packages:

```sh
mise bootstrap packages apply --manager apt
```

3. Install locked npm dependencies:

```sh
mise run deps:npm
```

### Configure the Applications repository

1. In the Applications repository root, trust the mise configuration:

```sh
cd ../applications
mise trust
```

2. Install npm dependencies:

```sh
npm ci
```

### Build guest applications

1. In the Applications repository root, compile the WebAssembly (Wasm) guest applications:

```sh
mise run build:applications
```

The compiled `wasm32-wasip1` binaries are placed in `target/wasm32-wasip1/release-wasm/`.

### Generate reference disk images

1. In the Platforms repository root, generate the native reference image from the released, signed packages pinned in `tools/fs_image/profiles/bundles.lock.json`:

```sh
mise run image:native
```

The LittleFS disk image is written to `target/seed/native/seed.img`. For the browser runtime, run `mise run image:browser` instead; it writes `target/seed/browser/seed.img`.

2. Optional: To seed the guests you built locally instead, bundle them into a new directory and pass it through `XILA_BUNDLES_DIR`. The output directory must not exist yet:

```sh
tools/bundle_applications.sh ../applications ../applications/target/wasm32-wasip1/release-wasm target/local-bundles
XILA_BUNDLES_DIR=target/local-bundles mise run image:native
```

### Configure local cross-repository overrides

The `Cargo.toml` manifests in each repository pin dependent Git revisions by default.

1. To develop across local working copies simultaneously, run the override script in the Platforms repository:

```sh
python3 tools/dev/local_overrides.py \
  --core ../core \
  --applications ../applications \
  --platforms . \
  --output /tmp/xila-local-overrides.toml
```

2. Pass the generated configuration file to Cargo commands:

```sh
cargo check --config /tmp/xila-local-overrides.toml -p xila-native-example
```

Do not commit temporary modifications to `Cargo.lock` that reference local paths.

## Verify the result

In the Platforms repository root, build the native runtime:

```sh
mise run build:native
```

The output confirms successful compilation of `xila-native-example`.

To verify the browser runtime assembly, run:

```sh
mise run check:browser
```

The check verifies compilation for the `wasm32-unknown-unknown` target.

To verify the embedded Arduino Nano 33 BLE build, run:

```sh
mise run build:nano-33-ble
```

The check verifies compilation for the `thumbv7em-none-eabihf` target.

## Troubleshooting

| Symptom                                                    | Cause                                              | Fix                                                                                                             |
| ---------------------------------------------------------- | -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Missing ALSA headers (`asoundlib.h`)                       | Host ALSA development packages not installed       | Run `mise bootstrap packages apply --manager apt` in the Platforms repository.                                  |
| Font converter failure                                     | npm dependencies missing                           | Run `npm ci` in the Platforms and Core repositories.                                                            |
| Cargo downloads remote Git dependencies during local edits | Local checkouts not wired into Cargo configuration | Generate a patch configuration with `python3 tools/dev/local_overrides.py` and pass `--config <path>` to Cargo. |
